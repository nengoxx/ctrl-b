# R47 — Per-message model/endpoint attribution: what peers persist and what they show

**Date:** 2026-08-20 · **Scope:** how peer agent-chat/LLM apps attribute the **model** and the
**provider/endpoint** to an individual assistant message — what is shown, where, what is persisted
(field names + shapes), and how a fallback or mid-thread switch is communicated. **Lane:** seven
peers read at HEAD from shallow clones (open-webui, LibreChat, AnythingLLM, opencode, Codex CLI,
LobeChat) plus the local Claude Code JSONL transcripts as a primary source; ChatGPT / Claude.ai /
T3 Chat via secondary evidence.

**Drives:** `docs/ISSUES.md` **ISS-5** (re-activated 2026-08-20) — `StreamReport.served`/`.degraded`
→ one persisted `source` object on `messages.meta` → a badge in the assistant who-line. Not yet
cited by a D-entry.

**Assumed known, not re-derived:** the `meta` JSON-column contract (`MessageRepo._dump_meta`, "keys
are added here, not columns"); `StreamReport` already carries `served`, `degraded`, `failures[]`,
`model`, `served_target` (`adapters/inference.py`); D48 friendly provider names.

**Confidence key:** **[V]** verified — I read the primary source (repo source file, live JSONL) ·
**[R]** reported — official docs or credible secondary · **[U]** unverified inference.

---

## 0. TL;DR

**The dominant convention is: persist *two named scalars* on the assistant row — the model id and
the provider/endpoint id — and render *the model name only*, small and low-contrast, in the same
meta row as the timestamp, joined by `·`.** Five of seven readable peers persist exactly that pair.
Provider is persisted by four and *displayed as text* by none.

**Nobody persists a "this was a fallback / degraded" flag on the message.** Codex CLI comes closest
with a first-class `ModelRerouteEvent { from_model, to_model, reason }` — but it is a *transient
notification*, not a message field; its own TUI drops it on the floor. Claude Code prints a notice
that "lasts for the current turn only". So ctrl-b's `degraded` bit is genuinely un-precedented, and
that is an argument for it being the thing worth showing, not the model name.

The single most on-point peer is **opencode**: its message meta row is literally a who-line —
`metaHead = "Build · Claude Sonnet 4"`, `metaTail = "14:32"`, separator ` · `, 12px
`text-text-weak` **[V]**. The single most useful *negative* datapoint is **AnythingLLM**: the only
peer that rules explicitly on mobile — `if (!metrics?.duration || !metrics?.outputTps || isMobile)
return null` **[V]**. It deletes the attribution footer on phones.

## 2. Per-peer notes (the load-bearing lines)

### open-webui — `01f4282`, 2026-07-27 **[V]**
Assistant messages are constructed client-side with a **snapshot of the display name next to the
id** (`src/lib/components/chat/Chat.svelte:2820-2824`):

```js
role: 'assistant', content: '', done: false,
model: model.id,
modelName: model.name ?? model.id,
modelIdx: modelIdx ? modelIdx : _modelIdx,
timestamp: Math.floor(Date.now() / 1000)
```

But the renderer prefers a **live catalog lookup**, falling back to the raw id, not to the snapshot
(`Messages/ResponseMessage.svelte:181, 672-675`):

```svelte
$: model = $models.find((m) => m.id === message.model);
<Tooltip content={model?.name ?? message.model} placement="top-start">
  <span id="response-message-model-name" class="line-clamp-1 …">{model?.name ?? message.model}</span>
```

So `modelName` looks **write-only** on the path I read — a persisted display-name snapshot that the
main view never consults. The arena reveal string is `RateComment.svelte:106-110`.

### LibreChat — `16e4d14`, 2026-08-19 **[V]**
Schema (`packages/data-schemas/src/schema/message.ts:25-31`) is two independent optional strings —
`model: {type: String, default: null}` and `endpoint: {type: String}` — plus a free-form
`metadata: Mixed`. The interesting part is the UI contract in
`client/src/components/Chat/Messages/ui/HeaderLabel.tsx`:

- `getHeaderModelName(...candidates)` picks the first candidate that is not an `agent_`/`asst_`
  document id — because "a message's `model` carries that id rather than a model name".
- The header renders `label` (the agent/assistant name) and `hoverLabel` (the model) in **one grid
  cell**, crossfading on hover *or* row focus — and **only when they differ**:
  `if (!hoverLabel || hoverLabel === label) return <span>{label}</span>`.
- Always-present screen-reader text: `com_ui_message_model` = **`"Model: {{0}}"`**.

### AnythingLLM — `b1b165e`, 2026-08-19 **[V]**
`workspace_chats` is `(prompt TEXT, response TEXT)` — the assistant side is one JSON blob. Providers
return a uniform `metrics` object (`server/utils/AiProviders/openAi/index.js:171-183`):

```js
metrics: { prompt_tokens, completion_tokens, total_tokens, outputTps, duration,
           model: this.model, provider: this.className, timestamp: new Date() }
```

which `stream.js:328-338` persists as `response.metrics`. The rendered string
(`…/Actions/RenderMetrics/index.jsx`) is `[model, "1.2s (34.50 tok/s)", "Aug 20, 3:14 PM"]
.filter(Boolean).join(" · ")` — **`provider` is dropped**. Visibility is `opacity-0` +
`md:group-hover:opacity-100`, pinnable by clicking (localStorage `anythingllm_show_chat_metrics`),
and **suppressed outright on mobile**.

### opencode — `b155b15`, 2026-08-20 **[V]**
Flat fields on the assistant message (`packages/sdk/js/src/gen/types.gen.ts:112-141`):
`modelID: string`, `providerID: string`, `mode: string`, `cost: number`,
`tokens: {input, output, reasoning, cache:{read, write}}`, `finish?: string`.

The name is resolved through the provider catalog with the id as fallback, and composed into a
who-line (`packages/session-ui/src/components/message-part.tsx:1214-1235`):

```ts
const match = data.store.provider?.all?.get(providerID)
return match?.models?.[modelID]?.name ?? modelID          // friendly name ?? raw id
…
const metaHead = () => [titlecase(agent), model()].filter(Boolean).join(" · ")
const metaTail = stamp        // Intl.DateTimeFormat(locale, { timeStyle: "short" })
```

Rendered as `data-slot="user-message-meta"` / `-sep` / `-meta-tail`, all
`class="text-12-regular text-text-weak cursor-default"`. The TUI's markdown export uses the same
grammar with duration appended (`packages/tui/src/util/transcript.ts:81-83`):
`## Assistant (Build · Claude Sonnet 4 · 12.3s)`.

**The attribution hangs off the *user* message**, not the assistant one — it reads as "this turn was
sent to X".

### Claude Code — local transcripts, 22 134 assistant records **[V]**
`~/.claude/projects/<slug>/<session>.jsonl`, one JSON object per line. Assistant records:

```
top-level: cwd, effort, entrypoint, gitBranch, isSidechain, message, parentUuid,
           requestId, sessionId, timestamp, type, userType, uuid, version
message:   content, diagnostics, id, model, role, stop_details, stop_reason, usage
```

Observed `message.model` values across this project's transcripts: `claude-fable-5` (16 993),
`claude-opus-5` (4 428), `claude-opus-4-8` (684), **`<synthetic>`** (29 — the sentinel for locally
generated assistant turns such as interrupts/errors; those rows also have no `effort` and no
`usage.service_tier`). `usage.service_tier` was `"standard"` on all 22 105 real rows.

Docs **[R]** (`code.claude.com/docs/en/model-config`): fallback chains "try them in order, showing a
notice when it switches. The switch lasts for the current turn only"; "Claude Code doesn't confirm
the chain at startup and `/status` doesn't display it. **The notice shown when a switch happens is
the first visible sign that a fallback is configured.**" Content-classifier fallback "re-runs the
request on that model and **shows a notice in the transcript**", after which "the session continues
on the fallback model".

### Codex CLI — `312b62a`, 2026-08-20 **[V]**
Rollout attribution is **per turn**, not per message: `TurnContextItem { …, model: String,
comp_hash, personality, effort, … }` written "once per real user turn"
(`codex-rs/protocol/src/protocol.rs:3027-3074`). `AgentMessageItem` (`items.rs:130-142`) carries
`id`, `content`, `phase?`, `memory_citation?` — no model.

The switch is its own protocol event (`protocol.rs:1965-1970`, `app-server-protocol/.../v2/model.rs:157-163`):

```rust
pub struct ModelRerouteEvent { pub from_model: String, pub to_model: String, pub reason: ModelRerouteReason }
pub struct ModelReroutedNotification { thread_id, turn_id, from_model, to_model, reason }   // "model/rerouted"
```

Rendered only in the non-interactive path (`exec/src/event_processor_with_human_output.rs:286-293`):
`eprintln!("{} {} -> {}", "model rerouted:".yellow().bold(), from_model, to_model)`. The TUI's
handler is `ServerNotification::ModelRerouted(_) => {}`.

### LobeChat — `3d75168`, 2026-08-20 **[V]**
Dedicated columns, not a blob (`packages/database/src/schemas/message.ts:110-118`):
`metadata jsonb`, `usage jsonb` ("promoted out of `metadata.usage` into a dedicated column"),
`model text`, `provider text`, `error jsonb`, `traceId`, `observationId`.

The footer is gated on a **user setting** (`Messages/AssistantGroup/index.tsx:168, 339-341`):
`const isDevMode = useUserStore(s => userGeneralSettingsSelectors.config(s).isDevMode)` →
`{isDevMode && model && <Usage model provider usage performance />}`. Inside `Usage` the model name
is `modelCard?.displayName || model` next to a `<ModelIcon>` brand glyph, `font-size: 12px`,
`colorTextQuaternary`, with TPS after a `·` and TTFT demoted into a tooltip — with an in-source
rationale worth stealing: *"at 12px a gauge glyph is indistinguishable from the neighbouring coin,
so the reader can't tell what the number measures"*. `provider` is used for lookup and for the
brand icon; it is never printed as a word.

### Wire-level note — OpenRouter **[R]**
The response body echoes `"model": "anthropic/claude-sonnet-4.5",  // The model that was selected`
after routing/fallback; there is no separate `provider` field. This is the same fact ctrl-b already
captures as `StreamReport.model` (Phase 18 / C-9) and persists as `meta.usage.model`.

## 3. Synthesis

**Dominant convention (5/7):** two named scalars on the assistant record — model id + provider id.
`model`+`endpoint` (LibreChat) · `model`+`provider` (LobeChat, AnythingLLM's `metrics`) ·
`modelID`+`providerID` (opencode). open-webui is the exception in *what* the second field is
(`modelName`, a display-name snapshot, not a provider).

**Dominant display:** the **model** name — friendly name resolved from a catalog, raw id as fallback
— rendered small (12px), low-contrast, in the same meta row as the timestamp, `·`-separated.

**Split on visibility:** always-on (open-webui, opencode) · hover/focus-reveal (LibreChat,
AnythingLLM) · setting-gated (LobeChat `isDevMode`, AnythingLLM's localStorage pin) · absent
(Claude Code, Codex TUI, Claude.ai).

**Outliers worth naming.** *Codex* attributes at the **turn**, not the message — one
`TurnContextItem` per user turn, nothing on the assistant item. *opencode* attaches the badge to the
**user/request** message. *AnythingLLM* is the only peer that rules on mobile, and its ruling is
**delete it**. *LobeChat* is the only peer that treats attribution as a power-user feature behind an
explicit toggle.

**What nobody does.**
1. **No peer persists a per-message "degraded / a fallback saved us" flag.** Not one. Codex's
   reroute is transient; Claude Code's notice is transient and turn-scoped.
2. **No peer renders the provider/endpoint as a word.** It is persisted (4 peers) for lookup, icons
   and cost math, then dropped from the visible string in favour of the model name.
3. **No peer persists the failed hops.** `StreamReport.failures[]` has no analogue.
4. **No peer shows attribution on a phone-width layout by default.** The two that thought about it
   (AnythingLLM, LobeChat) both hide it.

The implication for ISS-5 is inverted from the usual "copy the field, copy the UI": copy the
**field shape** (peers agree), but do **not** copy the UI, because the fact ctrl-b has and peers
don't (`degraded`) is exactly the fact that earns space on a 420px line, and the fact peers show
(the model name) is the one they all hide on mobile.

## 4. Recommendation for ctrl-b

### (a) The persisted `source` object

| | Shape written into `messages.meta` | Trade-off |
|---|---|---|
| **A — two flat sibling keys** | `"served": "openrouter"`, `"degraded": true` | Cheapest to write and read; but scatters three facets of one event across `meta.usage.model` + two loose siblings, and the next routing dimension (`failures`, `attempts`, `from`) becomes a fourth loose key — the shape the repo's "extend, don't migrate" directive exists to prevent |
| **B — one `source` object beside `usage` (the ISS-5 plan)** | `"source": {"served": "openrouter", "degraded": true, "from": "corsair"}` — `from` present only when degraded | Matches AnythingLLM's `metrics{}` grouping and Codex's `from→to` pair; every future routing fact (`attempts`, `failures[]`, `served_target.context_window`) is one additive key inside an object that already exists. Cost: the *model* stays in `usage.model`, so "who answered" reads from two places |
| **C — `source` absorbs the model, `usage` goes purely numeric** | `"source": {"served": …, "model": …, "degraded": …}` + `usage: {input_tokens, output_tokens}` | Conceptually cleanest and closest to the peer pair (`model` + `provider` side by side). Cost: a real migration — `usage.model` is written for every assistant turn since Phase 18/C-9 and is not sparse, and the no-legacy-seams rule means fold + write-back + downstream rewrite |

**I would pick B.** It is the ISS-5 seam as designed, it is the peer-attested grouping, and it is
the only option that is purely additive today. The honest caveat is that C is the shape a
green-field design would choose — so if the owner wants to pay one migration now while the routing
data is still young, C is defensible and B is not "wrong later", just "split later". Rider if B:
write down that `usage.model` is the model-of-record and `source` is the *routing* record, so the
badge reads `source.served` and nobody duplicates the model string into `source`.

`from` is worth including from day one: it is the only field that lets the badge say *what* was lost,
and Codex is the one peer precedent for communicating a switch (`from_model → to_model`).

### (b) The badge UX at 420px

The who-line is a 10px uppercase caption; today it reads `⏺ ASSISTANT · 14:32`.

| | Rendering | Trade-off |
|---|---|---|
| **1 — always-on endpoint chip** | normal `⏺ ASSISTANT · CORSAIR · 14:32` · degraded `⏺ ASSISTANT · OPENROUTER · 14:32` in the warn token | Ambient "which box is warm" awareness with zero interaction; but it adds a permanent third segment to a 10px line and repeats the same word for 40 turns straight. This is what open-webui/opencode do — on desktop |
| **2 — exception-only marker** | normal: **unchanged** · degraded `⏺ ASSISTANT · ↯ OPENROUTER · 14:32` (warn token, `aria-label="served by openrouter after a fallback"`) | The line stays exactly as it is on the happy path and the badge carries real information every single time it appears. Cost: "which endpoint served this normal turn?" is not answerable from the line |
| **3 — dot-as-state + reveal on demand** | the existing `::before` who-dot takes the endpoint's colour; the endpoint word replaces the timestamp on hover/tap (LibreChat's crossfade, one grid cell so nothing reflows) | Densest and most elegant; but colour alone is not an accessible signal, and a tap-to-reveal on mobile is a discovery problem the owner would have to remember exists |

**I would pick 2, with 3's crossfade as an optional rider** (tap the who-line to swap `14:32` →
`CORSAIR` for a couple of seconds, so the normal-turn question is answerable without spending line
budget). Reasons: (i) the owner's stated pain is *"which endpoint served this **varies** turn to
turn"* — variance is the signal, and option 2 renders exactly the variance; (ii) at 420px the 10px
who-line's practical budget is roughly 30–35 characters **[U — estimate, not measured]**, and
`ASSISTANT · ↯ OPENROUTER · 14:32` (31) fits while a permanent chip plus a degraded marker would
not; (iii) the two peers that ruled on mobile both removed the always-on badge; (iv) it inverts
cheaply — if the owner later wants ambient awareness, option 1 is the same component with the
condition deleted.

Option 1 is the right call **if** the owner's real want is ambient telemetry ("is corsair up right
now?") rather than an alert. That is a genuine preference, not a technical question — hence the menu.

**Strings.** Use the D48 friendly provider name with the raw id as fallback, mirroring opencode's
`models[modelID].name ?? modelID`: `friendlyName(source.served) ?? source.served`, uppercased by the
caption's existing text-transform. Screen-reader text should follow LibreChat's precedent
(`"Model: {{0}}"`): a non-hiding `sr-only` span reading `served by openrouter (fallback from
corsair)`. Do **not** print the model id in the who-line — every peer that had the choice printed
the *friendly* name, and ctrl-b's model ids (`qwen3.6-max`, `gemma-3-27b-it-Q4_K_M`) are worse at
10px than the endpoint names the owner already chose.
